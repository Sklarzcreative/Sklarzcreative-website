# Publishing contract

1. Read `config/publishing-routes.json` before each write. Resolve the exact account/channel via a harmless provider read. One destination has one primary publisher; unassigned routes stay on HOLD. A timeout is not permission to switch providers.
2. Metricool owns the six named Sklarz routes; Buffer owns personal LinkedIn, X and the single Cassandra Substack Notes profile. No automatic company LinkedIn route. Full newsletters remain native Substack work.
3. Preserve the direct publisher's disabled/dry-run configuration, limits, approval gate and stale-backlog protections. Do not start its loop, enable GitHub Actions publishing, feed it live rows, or reactivate Make. A successful test alone is not authorization to activate it.
4. Inspect pending and recently published jobs before writing. Match provider post ID first, then destination, source/anchor ID, copy, media, timing and topic. Topic overlap can be purposeful repurposing; do not block reuse merely because an approved asset URL was used before. Reject redundant jobs or cosmetic rewrites without a distinct purpose.
5. Apply approval, final-copy quality, source verification, media rights and platform compatibility checks. Verify actual current plan allowance and queue capacity. If allowance cannot be established, preserve the queue, prepare drafts locally and record the scheduling blocker. Do not infer a monthly quota from an old screenshot or assume a returned limit is per-channel.
6. Before a write, record the intended destination, copy fingerprint, source, time in UTC and America/New_York, approval basis and planned provider. Recheck the destination queue immediately before submission. Do not run overlapping scheduling sessions; if another run may be active and cannot be reconciled, hold new writes. This instruction pack does not implement a distributed lock.
7. Submit via only the designated provider. Save returned ID and status, then read it back when supported. A write timeout/unknown outcome requires reconciliation before retrying; do not blindly resubmit. Use provider idempotency features when actually available, never invented parameters.
8. Distinguish draft, scheduled, sending, published and failed. Published requires provider confirmation; record its URL when returned. An accepted task launch or schedule request does not prove publication. Never invent missing URLs or analytics.
9. Record evidence and blockers in the existing Trello card, preserving other project notes. Use existing workbook fields only when their purpose is verified. If record writing fails, save a local receipt and report the failure, rather than recreating the post.
10. Credentials stay in the environment's secure store. Never include tokens, OAuth callback codes or passwords in this pack, prompts, Sheets, receipts or commits. Do not copy workspace credentials into another host to bypass missing access.

The registry is a shared instruction contract, not provider-side enforcement. A durable cross-run lock/receipt mechanism should reuse existing infrastructure and requires implementation validation before it can be claimed operational.
